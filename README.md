# Runner (working title)

A browser-based endless runner built with HTML, CSS, vanilla JavaScript and Canvas. No build step or dependencies.

## Run locally

ES modules need a server (opening `index.html` directly won't work):

```bash
python -m http.server 8000
```

or, with Node:

```bash
npx serve .
```

Then open the printed URL (http://localhost:8000 for the Python command).

## Controls

- **Space** or **ArrowUp**: start / jump
- **ArrowDown** or **S** (hold): crawl under hanging obstacles. The crawl lasts at least a short minimum time, and won't end while you're still under an obstacle.
- **Touch (portrait-first):** large **Jump** (right) and **Crawl** (left, hold) buttons below the game. Tapping the game also starts and jumps. In landscape the buttons sit either side of the game.
- **Restart** button (or Space / tap) after Game Over. Restart is ignored for a moment after dying so a held key can't skip the screen.

Your best score is saved in your browser (`localStorage`) and never leaves it.

## Tuning

All gameplay constants are in `scripts/config.js`: physics, speed ramp, scoring, obstacle variants, and difficulty tiers.

## PWA (install and offline)

`manifest.webmanifest`, `sw.js` and `icons/` make the game installable (portrait, standalone) and playable offline. Service workers need HTTPS (or `localhost`).

- **Shipping an update:** change `CACHE_VERSION` in `sw.js`. The new version installs in the background and takes over on the next page load.
- **Adding a file** that the pages load: add it to `PRECACHE` in `sw.js` (`node tests/run.mjs` fails if you forget).
- **Icons:** placeholders generated by `node tools/make-icons.mjs`; replace the art there, or drop in your own PNGs with the same names.
- **Name:** "Runner" is a placeholder. When the final name is chosen, update the `<title>`/meta tags in the HTML pages, `manifest.webmanifest`, `contact.html`/`privacy.html`, and the share text in `scripts/game.js`.

## Contact form

`contact.html` stays on a "not set up yet" notice until `FORM_ENDPOINT` in `scripts/contact.js` is set to the URL from your form service (e.g. Formspree or Web3Forms). Form endpoints are public by design; keep private keys in the service's dashboard, never in this repo.

## Deploying (Railway)

The site is static. `Dockerfile` + `Caddyfile` serve it with Caddy on Railway's `$PORT` (HTML and `sw.js` are always revalidated; assets cache for an hour; gzip on).

1. Create a Railway project from this folder (GitHub repo or `railway up`). Railway detects the `Dockerfile`.
2. Generate a public domain in the service's Networking settings (HTTPS is automatic).
3. Test the **deployed** site: play it, install it, go offline and reload, check the contact form once configured.

Railway is a paid service after its trial credit; check current pricing before deploying. Any static host works with this folder.

## Tests

Check the service worker and page wiring too:

```bash
node tests/sw.test.mjs
```

Headless checks for obstacle fairness (minimum gaps, tier unlocks, a reactive bot that must survive long runs), score/speed progression, and best-score storage handling:

```bash
node tests/run.mjs
```
